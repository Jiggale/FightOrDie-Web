# 项目事实源

> 状态：v0 讨论基线  
> 更新日期：2026-11-05  
> 本文不代替 `DECISIONS.md`。两者冲突时，以最新确认的决定为准。

## 项目目标

《燃薪者》首先制作一个可验证的垂直切片，用于：

1. 验证“燃烧生存 + 持烬者竞争 + 自主契灵”是否成立；
2. 形成课程作品或求职作品集；
3. 在体验成立后评估商业独立游戏方向。

## 当前产品定义

一款单人、剧情驱动的双世界生存 RPG。持烬者点燃自身后获得力量，但必须持续消耗余烬才能维持生命。战斗会加速燃烧，并可能产生新的余烬；其他持烬者和死亡事件都处于这一资源循环之中。

主角与一只有独立目标、可以拒绝和谈判的契灵建立不完全受控的契约。

## 必须保留

- 表世界与里侧的双世界结构；
- 多名持烬者为了生存和力量产生竞争；
- 余烬来自死亡，是死者的残留而非普通货币；
- 契灵是有自主目标、判断和拒绝权的个体；
- 战斗既有收益也有额外燃烧代价；
- 不杀人不代表没有代价，必须存在更低收益或更高成本的替代方案。

## 可选或待验证

- 主角在设定上完全没有私欲；
- 任何一方死亡都会留下余烬；
- 灯芯持续消耗余烬；
- 侵蚀达到上限后死亡；
- 原住民的等级与派系；
- 回合制是最终战斗形式；
- 主角是否保留“遗物整理师”身份。

## 非核心与明确禁止

- 不把遗物调查做成一整套独立推理游戏；
- 不把契灵做成可收集、升级、完全服从的宠物系统；
- 不从 v1 开始同时实现派系经营、庞大技能树、装备刷取和多结局全量内容；
- 不因 agent 建议而新增系统，除非用户明确批准并写入 `DECISIONS.md`；
- 不让文戏消费玩家资源后只给予纯文本，必须提供情报、关系或路线收益。

## V0 核心循环

```text
燃烧负担即将到期
→ 发生死亡事件或发现可争夺资源
→ 玩家选择调查、交易、狩猎或接受契灵帮助
→ 处理持烬者或里侧威胁
→ 获得并分配余烬
→ 承担契灵承诺、关系和世界后果
→ 燃烧成本上升，进入下一轮
```

## V0 垂直切片范围

- 一个主角；
- 一只契灵；
- 一个死亡事件；
- 一场主要战斗；
- 至少一种低收益、高成本的非致命解决路线；
- 一次契灵承诺；
- 一次余烬分配与章节结算；
- 一个可见的后续后果。

## 死亡调查的定位

死亡调查是可选支线，用于推进剧情、发现敌人弱点、获得契灵契约条件或解锁替代路线。不要把它宣传成游戏的主要类型，也不要在 V0 中制作大型线索板和复杂推理界面。

## 当前原型技术基线

- 前端：Vue 3 + TypeScript + Vite；
- 后端：Spring Boot；
- 对白与分支：ink，使用 Inky 编写和预览；
- 当前 Web 架构用于原型和作品集，不代表最终商业发行架构。

## 成功标准

一名玩家在 15—30 分钟内能够理解：

1. 自己为什么必须获得余烬；
2. 一场战斗消耗了什么、产出了什么；
3. 契灵为什么不能像宠物一样使唤；
4. 在杀死目标与承担更高代价之间存在真实取舍；
5. 自己的选择如何改变下一次生存压力或契灵关系。
